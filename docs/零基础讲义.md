# 零基础讲义：从"强化学习是什么"到"LORO 在做什么"

> 面向：没学过强化学习、第一次做论文复现的同学
> 用途：组内培训；研读汇报第 2–4 页的底稿
> 配套论文：Improving the Data-efficiency of Reinforcement Learning by Warm-starting with LLM（LORO，arXiv 2505.10861）

## 0. 先记住这句话

一个笨蛋，在一个世界里反复试错，靠"得分"慢慢变聪明。

强化学习（Reinforcement Learning，RL）就这一句，剩下的都是细节。

## 1. 强化学习是什么

### 1.1 四个词

拿 CartPole（小车顶杆子）举例：

- **状态（state）**：现在的情况。比如"杆子歪了 0.02 弧度，小车速度 0.04"。
- **动作（action）**：你能做的选择。往左推，或往右推。
- **奖励（reward）**：这一步得了多少分。杆子没倒，加 1。
- **回合（episode）**：从开始到失败算一局。杆子倒了，这局结束。

### 1.2 一局长什么样

```
第 1 步：杆子略歪   → 往左推 → 没倒 → +1
第 2 步：杆子回正   → 往右推 → 没倒 → +1
...
第 180 步：杆子倒了 → 本局结束 → 总分 180
```

所有步的奖励加起来叫**回报（return）**。RL 只有一个目标：让每一局的回报尽量高。

### 1.3 什么是"策略"

策略就是"看到什么情况就做什么动作"的那张表。

- 杆子往右歪 → 往右推
- 杆子往左歪 → 往左推

这张表可以是人手写的规则，可以是一个神经网络，也可以是一个大模型——这篇论文用的就是大模型。

**学习 = 修改这张表，让回报变高。**

## 2. "学习"到底在学什么

### 2.1 Q 值

一个动作好不好，不能只看眼前这一步。往左推这一步加 1 分，但可能三步之后杆子就倒了。所以要算"从这个动作开始往后一共能拿多少分"。

这个数叫 **Q 值**：在状态 s 下做动作 a，长期来看值多少分。

学习的过程就是不断修正 Q 值，让它越来越准。

### 2.2 一个能算出来的例子

一条直线上 4 个格子，走到最右格得 1 分，其他步得 0 分：

```
[1]  [2]  [3]  [4: 得 1 分]
```

一开始所有 Q 都是 0，也就是"什么都不知道"。

第一次尝试：从 3 往右走，到了 4，拿到 1 分。更新（学习率取 0.1）：

```
Q(3, 右) = 0 + 0.1 × (1 - 0) = 0.1
```

反复走，`Q(3, 右)` 从 0.1 → 0.19 → 0.27 → …… 逐渐逼近 1.0。

然后，站在 2 号格的人发现"我往右走，下一步的 Q 已经是 1.0 了"，于是他更新（折扣因子取 0.9）：

```
Q(2, 右) = 0 + 0.1 × (0 + 0.9 × 1.0 - 0) = 0.09
```

再反复，`Q(2, 右)` 也逼近 1.0，然后才轮到 `Q(1, 右)`。

### 2.3 关键的一幅画面：回声

请大家记住这里发生了什么：

> **那个"1 分"的价值，是从终点一个格子一个格子往回"传"的。每传一格，都要真的跑一次。**

**这就是 RL 慢的根本原因。** 不是算法笨，是分数必须靠腿一步步跑回来。

这个画面是理解整篇论文的钥匙：路越长、越反直觉，"回声"传得越慢，RL 就学得越吃力。

## 3. 为什么 RL 慢

### 3.1 样本效率

**样本效率（sample efficiency）= 要学会这件事，需要跟环境交互多少次。**

- 效率低：要练一万局才学会 → 贵、慢，真实世界里还可能危险（机器人摔一万次）
- 效率高：练一百局就会 → 便宜

论文标题里的 "Data-efficiency" 说的就是这个。

### 3.2 用 MountainCar 看清问题

MountainCar：小车在谷底，只能左右推。推力不够直接上坡，**必须先往左退，攒够速度再冲上右坡**。

奖励规则：每过一步减 1 分，到山顶结束。所以：

- 一局最多 200 步 → 最差 −200
- 会开的人约 100 步到 → −100
- 不会开的人原地晃 200 步 → −200

论文里的数字（累计回报除以局数，得到平均每局）：

| 谁 | 平均每局 | 翻译成人话 |
| --- | --- | --- |
| 随机乱按 | −200 | 200 步，一步没上去 |
| 纯 Qwen-7B 打 | −200 | 一样，7B 不会开 |
| 从零学的 RL | −192 | 练了 300 局，还是不会 |
| LORO（论文方法） | −152 | 152 步上山，学会了 |
| 纯 Qwen-32B 打 | −100 | 100 步，比 LORO 还好 |

看第三行：**从零学的 RL 练了 300 局，跟乱按差不多。** 这就是论文要治的病。

### 3.3 死结

回到第 2.3 节的回声。MountainCar 里，"到山顶"这个信号要沿着"先左退、再右冲"这条很长又反直觉的路径往回传。而 RL 一开始只会往右推，永远卡在谷底，那个信号永远传不回来。

> **得分传不回来 → 学不到 → 继续乱走 → 得分还是传不回来。**

## 4. 大模型（LLM）插手的位置

### 4.1 三种可能

在 RL 里插一个大模型，通常只有三种插法：

- **写奖励**：让大模型写一个奖励函数，再交给 RL 训练。
- **当策略**：让大模型每一步看着状态直接选动作。
- **给反馈**：让大模型看训练曲线，提出改进建议，循环几轮。

### 4.2 这篇论文选的是"当策略"

LORO 让 Qwen2.5 每一步读取文字化的状态，输出一段思考（Chain-of-Thought，CoT），最后给一个动作编号。

例如 CartPole：

```
【系统提示】你在玩 CartPole……输入 1 表示向左推，2 表示向右推。
【用户输入】小车位置 0.006，速度 0.04 向右；杆子倾斜 0.02 弧度，角速度 0.02 向右。
            请一步一步思考。
【模型输出】先分析位置、速度、角度、角速度……杆子有向右倒的趋势，
            应该把小车往左移来抵消。Action: 1
```

程序从回答里取最后一个数字，作为动作。

### 4.3 一个类比

想象你要学打台球。

- **纯 RL**：没人教，自己打一万杆。只知道进没进，不知道姿势对不对。慢，但最后能学会。
- **纯 LLM**：请一个读过所有台球书、但自己没下过场的人替你打。他懂原理、大方向对，但手上没准头。
- **LORO**：让这个书呆子先打 10 局，你在旁边录像；然后你拿着这 10 局录像反复研究（预训练）；最后自己上场练（在线训练）。

书呆子打得不好，但他的 10 局里几乎没有"把球打到隔壁桌"这种离谱操作——他走的是正道，只是不够精。

**你要的不是他的技术，是他的路线。**

### 4.4 方法四步

```
第 1 步：让 Qwen 打 10 局              （已经比随机强很多）
第 2 步：把这 10 局的记录存下来        （状态、动作、奖励，约 500～3000 条）
第 3 步：RL 先照着这 10 局学          （离线预训练 1000 步）
第 4 步：LLM 退场，RL 自己上场练       （在线训练，边打边改）
```

**第 4 步很关键：大模型只在最开始出现，之后完全不参与。** 所以它便宜——总共两千次调用左右，几块钱。

### 4.5 全文最关键的一个假设

论文的 Assumption 1 说的是：

> **LLM 的策略不需要最优，只需要"覆盖"最优策略会走到的那些状态。**

翻译：**书呆子不需要打得准，只需要别把球打到隔壁桌。**

为什么这个假设巧妙？它把"大模型不够强"这个缺点，变成了"只要大方向对就行"这个很弱的条件。而 RL 最缺的恰恰就是大方向。

### 4.6 为什么还要在线再练

因为那 10 局是有偏的：模型只会走它熟悉的路线，遇到没见过的情况就懵。只学这 10 局，最多学到"书呆子的水平"。

所以最后必须自己上场，用真实反馈修正。论文把这个叫 **distribution shift（分布偏移）**：教材里的情况和真实情况不完全一样。

论文的对照实验很说明问题：

- 只用 LLM 的 10 局预训练、不再在线练 → 效果一般
- 只把 LLM 的 10 局混进在线数据、不先预训练 → 差很多
- 先预训练、再在线练 → 最好

**教材要先通读一遍再用，不能边打边翻。**

## 5. 把论文的数字翻译成人话

论文 Fig.2 报的是"累计回报"，数字很难读。换算成"平均每局"：

| 环境 | 指标 | 乱按 | Qwen-7B | 从零学 RL | LORO |
| --- | --- | --- | --- | --- | --- |
| MountainCar | 上山步数（越少越好） | 200 | 200 | 192 | 152 |
| CliffWalking | 步数（越少越好） | 2063 | 738 | 209 | 52 |
| FrozenLake | 成功率 | 2.7% | 0% | 50% | 63% |
| CartPole | 坚持步数（越多越好） | 20 | 34 | 163 | 181 |

三点解读：

- **CliffWalking 是论文"4 倍"的来源**：从零学平均要走 209 步（老掉悬崖），LORO 只要 52 步。
- **CartPole 提升很小**（163 → 181），因为这道题太简单，从零学也能学会。
- **MountainCar 最能说明问题**：从零学练 300 局仍是 192 步（等于没学会），LORO 是 152 步。

## 6. 五句话总结

1. **RL = 试错 + 得分 + 改策略**，目标只有一个：让每局回报更高。
2. **RL 慢，是因为"得分"要从终点一步步传回来**；路越长、越反直觉，传得越慢。
3. **LLM 的作用是提前把路指对**：它不最优，但它不荒唐。
4. **LORO = 让 LLM 先打 10 局 → 拿这 10 局当教材预训练 → 再自己上场练**；LLM 只出现在开头。
5. **论文的核心论点是一句很弱的话**：LLM 不需要强，只需要"覆盖"好路线——这是它能接上离线 RL 理论、并且便宜可用的原因。

## 附录 B：四个常见误解

- **误解一：LLM 在这篇论文里写代码。** 不是。它只是每步选一个动作，像个玩家。
- **误解二：要一直调用大模型。** 不是。只在前 10 局用，之后整个流程没有大模型。
- **误解三：LLM 越强，效果越好。** 论文自己的消融说：7B 和 32B 没有一致优势，0.5B 完全没用。
- **误解四：RL 学不好就是代码有 bug。** 很可能不是，而是这篇论文说的"样本效率太低"，那是方法问题，不是代码问题。
